# The Perspective — V1.1 Profile Network / PN-01 implementation contract

Status: **V1.1 FEATURE BRANCH — NOT RELEASED**

Baseline: `main@3fa80397963761d29d4e972fadf4f098e50e8c75`.
Scope: Company-profile public **read foundation** only. No production/staging deploy, CRM exposure, automated import, ownership-claim approval, or public sample content.

## Canonical boundaries

- `/companies` is the public company-directory route; `/companies/[slug]` displays one editorially approved company profile. Existing `/business/companies`, `/people/[slug]` and `/author/[slug]` remain unchanged.
- Public companies live in separate `profiles.company_profiles` editorial identity records and append-only `profiles.company_versions`. Never infer or copy a record from private `crm.companies`, `iam.people`, or tenant resources.
- Only the version explicitly selected by a `PUBLISHED` profile, with a recorded editorial approval timestamp and at least one source citation, can appear in a directory/detail response. Unpublished, withdrawn and wrong-profile versions never appear.
- The database function exposes an *allowlist* of public columns only. The `perspective_public` role can execute the functions, not SELECT the underlying tables. No browser-supplied organization/tenant identifier is accepted or set.
- Editorial provenance lives in the approved immutable version. No new writes or profile publishing routes are authorized in PN-01; future private workflow must obtain separate authorization and audit contracts.
- Do not assign verification badges. Editorial approval is not identity verification. Clearly disclose sponsored or commissioned material.
- No fake, fictional or unsourced editorial company profiles are seeded. An empty directory is a valid safe state, not a data defect.
- No schema migration can run against production or the V1.0 staging database as part of this branch. Verify migration and tests against a disposable V1.1 PostgreSQL 16 environment first. Release approval is separate from this implementation.

## PN-01 acceptance matrix

| Requirement | Required proof |
|---|---|
| Isolation | Public functions never join private CRM, account, client, billing or outreach tables |
| Publication | Only `PUBLISHED` plus editor-approved, source-backed versions are returned |
| Versioning | Approved snapshots are immutable; published version must belong to the same company |
| Direct-read privilege | `perspective_public` has EXECUTE on safe functions but no table SELECT/INSERT/UPDATE/DELETE |
| Bad input | Reject invalid slugs, malformed/sensitive projection fields and unsafe source URLs |
| URLs | Canonical metadata, noindex for empty directory, 404 for absent/unpublished profile |
| UX | Responsive directory and detail, accessible source/correction navigation, clear disclosure |
| Safety | No CRM-derived content, demo seed, production deployment, new external provider or DNS change |
| Qualification | Prisma schema validation, PostgreSQL migration/role checks, unit tests, typecheck, lint, production build and exact-head CI |

No V1.1 functionality is accepted as production-ready by this document alone. Existing V1.0 release work remains independent.
